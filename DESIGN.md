# WalletLedger direction

Reading this as: a wallet and journal workstation for a developer explaining transactional transfers, using a light financial register visual language. ENERGY 2 / RHYTHM 3 / MOTION 1.

Use warm paper #f5f3ec, white entry documents, ink #24372f, muted #53645b, deep forest header #163d30, forest action #225e45, attention/focus #9b4217, control borders #718477. Measure text at least4.5:1 and control boundaries3:1. Color accompanies words. System sans-serif supports forms; tabular numerals align money. No external decorative assets, new pictorial logo, gradients, glow or fake statistics. The wordmark is text.

Desktop: a compact header, narrow navigation rail and a working register. The principal balance is large with the currency and explicit simulation label. Recent transactions use readable rows rather than a tiled KPI wall. A transfer document is focused and narrow; a transaction detail shows the two journal legs and the debit/credit totals. Admin allocation, accounts and reconciliation have distinct table/form compositions. Use actual server counts and balances.

Phone: navigation wraps, amount and action remain readable, transaction rows become labeled blocks, journal tables have a labeled internal scroll region if needed. No document overflow. Target44px, visible labels, native inputs/select/dialog, Escape/focus restoration, useful loading/empty/error/unknown-outcome states. Text must work at200%. Motion is limited to focus/feedback and honors reduced motion.

The register motif comes from numbered transactions, paired debit/credit and explicit receipt status. Forest marks committed primary actions; attention marks recoverable errors. Whitespace separates balance, instructions and journal evidence. All money is synthetic IDR with integer rupiah; explain that in the interface. No fabricated security/compliance/performance or customer claims. Root personally reviews actual production screenshots and runs the four-block Delivery Gate.
