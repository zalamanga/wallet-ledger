## Entities and arithmetic

Workspace(id UUID,name). User(id UUID,email,full_name,role Admin|Member,password hash,created_at); one wallet per user plus one system funding wallet. Wallet(id UUID,user_id nullable,owner_name,is_system,currency IDR,balance_minor decimal-string,created_at). Balance normal is CREDIT minus DEBIT for every wallet. User wallets0..1e12, system wallet-1e14..0. All journal amounts positive integer1..1e9 per command. No fractions/sign/exponent/leading zeros or numeric JSON accepted for command amounts. Store BIGINT SQL, int64 Go, strings DTO/TypeScript.

Funding: admin debits the system wallet and credits a user wallet; label allocation of synthetic balance. Transfer: debit sender and credit recipient in one transaction; sender must own source wallet, recipient is another active user. Reversal: Admin may reverse a TRANSFER once, with original receiver debit and sender credit; receiver must have enough. Funding/reversal cannot be reversed. No journal mutation/deletion. Distinct UUID reversal transaction, original retained; transaction has reversal_id/reversal_of metadata from relation (never alter original journal). Denial409 for insufficient funds or cap, no partial state. Each accepted transaction exactly2 distinct wallet legs, DEBIT and CREDIT totals equal, with wallets/cache/receipt/audit atomic. Balance cache equals signed journal sum. Deferrable PostgreSQL triggers enforce balancing/cache/shape plus immutable journal/transactions/receipts/audit including truncate guards; runtime role is not schema owner. No unrestricted direct table mutation route. Public deployment/payment integrations/real money outside scope.
